## Summary

Feature 002 adds a members-only forum to the Varodd prototype. People working at E-Waves member businesses post questions, answer each other, search and browse by topic, see similar questions before posting, and flag problems that Varodd administrators review afterwards. A simulated chatbot answers a fixed list of prepared questions from seeded forum content. It always shows a trust notice, and it gives a no-answer response when its sources are missing, flagged, or removed.

Technical approach: 002 is a second feature in 001's single-page app and uses its stack and shared frame unchanged (constitution I). It registers one `FeatureDefinition` and one seed module. All rules are pure TypeScript commands and read functions tested first with Vitest, including simple word matching for search and similar questions and the chatbot's response rules. The chatbot is a pure function, not a stored conversation. A few shared frame files are extended rather than copied: the `DemoState` type, seed loading, an optional `requiredGroup` on activity audiences, a shared `SearchField`, and the secondary link row moved from the marketplace feature to the frame. Details and reasons are in [research.md](./research.md).

## Technical Context

**Language/Version**: TypeScript 7.0 (strict) on Node.js 26; React 19.3. Same as 001.

**Primary Dependencies**: The same as 001: React Aria Components 1.22, `@internationalized/date`, React Router 8 (hash URLs), Zod 4, the self-hosted Bree Serif and Barlow fonts. No new dependencies ([research.md §1](./research.md#1-stack)).

**Storage**: The shared browser `localStorage` state from 001, with a new `knowledgeBase` part. Seed data in the shared `src/seed/seed-data.json`, generated by `pnpm seed` with a new module `scripts/seed/knowledge-base.ts`. The bundled seed ID changes, so stored demo data from before 002 is replaced by the new seed when the app loads.

**Testing**: Vitest 5 + React Testing Library + `jest-axe` for rules, seed checks, and components; Playwright 1.65 + `@axe-core/playwright` at desktop (1280×800, Chromium) and mobile (390×844, WebKit) sizes. Playwright runs with at most 2 workers to keep CPU use down.

**Target Platform**: Same as 001: current desktop browsers, Safari on iOS, Chrome on Android, served as static files.

**Project Type**: Single-page web application (frontend only), the existing project at the repository root.

**Performance Goals**: Every command, search, and similar-question update finishes in under 100 ms on a normal laptop, on about 20 questions. First load stays under 2 seconds.

**Constraints**: WCAG 2.1 AA. Norwegian Bokmål. No network requests at runtime and no real AI or chatbot service; the chatbot is a visible simulation (constitution II). Only the shared design tokens and components (constitution IV, FR-023). Separate desktop and mobile layouts. Content reflows down to 320 px.

**Scale/Scope**: 5 topics, about 16 seeded questions, 7 prepared chatbot questions, 3 near-duplicate examples, 4 member people at 3 member businesses. 7 pages (see [contracts/routes.md](./contracts/routes.md)), 6 commands and 7 read functions (see [contracts/commands.md](./contracts/commands.md)), 1 new shared component (`SearchField`) and 1 moved shared component (`SubNav`).

No item is left as NEEDS CLARIFICATION. The stack is inherited from 001, and the open technical questions are settled in [research.md](./research.md).

## Implementation Notes

- Code is written by subagents running Claude Sonnet 5.5 (`claude-sonnet-5-5`) at medium reasoning effort, with the main agent coordinating the tasks and checking the results.
- No comments in code (project owner's rule).
- Domain functions take time and the acting person as inputs and never read the clock, so tests use fixed times.
- Interface text is written directly in Norwegian Bokmål in the warm "du"/"vi" tone of 001's Design Language section.
- Two points the spec left open are settled here. Authors see why their content was flagged but not who flagged it ([research.md §6](./research.md#6-moderation)). The chatbot's offer to post opens the question form with the title filled in ([research.md §5](./research.md#5-simulated-chatbot)).
