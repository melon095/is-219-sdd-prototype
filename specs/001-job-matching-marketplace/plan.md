## Summary

Feature 001 is a clickable, Norwegian-language prototype in which business owners publish small task requests, the system builds ranked shortlists of up to 3 workers by skill share and start date, and the owner takes one worker from interview through offer, agreement, and completion, with a permanent log and private conversations on every request. NAV referrals and website crawling are visible simulations. Because 001 is built first, it also builds the shared frame for every Varodd feature: home page, header with feature buttons, user switcher, activity feed, demo reset, seed data step, time debug buttons, and the Varodd design language.

Technical approach: a static React 19 + TypeScript single-page app built with Vite and managed with pnpm. All business rules are pure TypeScript functions driven by commands, so they can be tested first and without a browser. Demo data lives in `localStorage` per browser, loaded from a committed, reproducibly generated seed file. The interface uses React Aria Components, copied from the Vanilla CSS starter kit and styled with plain CSS and Varodd design tokens, with AA-compliant text colours added. Dates use the `nb-NO` locale. Details and reasons are in [research.md](./research.md).

## Technical Context

**Language/Version**: TypeScript 7.0 (strict) on Node.js 26; React 19.3. See [research.md §1](./research.md#1-language-framework-and-package-manager) for the TypeScript 6 fallback.

**Primary Dependencies**: React Aria Components 1.22 and `@internationalized/date` 3.12; React Router 8 (hash URLs); Zod 4 (checking stored data and the seed file); `@fontsource/bree-serif` and `@fontsource/barlow` 5.3. Dev: Vite 8, `@vitejs/plugin-react` 6, `tsx` 4, Biome 2.6 for linting and formatting (no ESLint or Prettier).

**Storage**: Browser `localStorage` only, one copy per browser (FR-031). Seed data in `src/seed/seed-data.json`, generated by `pnpm seed`. No server and no database. See [contracts/seed-and-storage.md](./contracts/seed-and-storage.md).

**Testing**: Vitest 5 with jsdom 31, React Testing Library 16, `@testing-library/user-event` 14, and `jest-axe` 11 for unit and component tests. Playwright 1.65 with `@axe-core/playwright` 4.14 for end-to-end and accessibility tests at desktop and mobile sizes.

**Target Platform**: Current versions of Chrome, Edge, Firefox, and Safari on desktop, and Safari on iOS and Chrome on Android. Served as static files from any static host.

**Project Type**: Single-page web application (frontend only), one project at the repository root.

**Performance Goals**: Every command and page change completes visibly in under 100 ms on a normal laptop; the data set is tens of records. First load under 2 seconds on a normal connection.

**Constraints**: WCAG 2.1 AA. Norwegian Bokmål interface. No runtime network requests except the app's own static files: no third-party fonts, analytics, or APIs (constitution principle II). Separate desktop and mobile layouts (FR-034). Every colour, font, and component style comes from the shared design tokens (principle IV). Content reflows down to 320 px wide.

**Scale/Scope**: About 5 businesses, 10–15 people, 5–8 worker profiles, 8–10 seeded requests. 9 pages (see [contracts/routes.md](./contracts/routes.md)), 19 domain commands (see [contracts/commands.md](./contracts/commands.md)), about 24 shared UI components.

No item is left as NEEDS CLARIFICATION; every open technical question is settled in [research.md](./research.md).

Only `src/app/features.ts` and the seed generator get one new line each.

## Implementation Notes

- Code is written by subagents running Claude Sonnet 5.5 (`claude-sonnet-5-5`) at medium reasoning effort, with the main agent coordinating the tasks and checking the results.
- No comments in code (project owner's rule).
- Domain functions take time and the acting person as inputs and never read the clock, so tests use fixed times.
- Interface text is written directly in Norwegian Bokmål in the warm "du"/"vi" tone of the spec's Design Language section.
